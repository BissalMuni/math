## ③ doc-ingest에 강화학습? — 당신의 "지도학습" 직관을 풀어볼게요

당신 생각: *정답지(expected.json) 있음 → 같은 문서를 계속 파싱 → 정해진 파싱 프롬프트로 → 정답에 가장 가까운 프롬프트를 만든다.*

핵심 교정: "정답지가 있다 = 지도학습"이 아니에요. 무엇을 *최적화*하느냐가 갈라요.
당신이 *생각한* 것	당신이 *실제로 묘사한* 것
정답지	있음	있음
바꾸는 대상	(암묵적으로 모델?)	프롬프트 텍스트
신호	"정답을 베껴라"(지도)	"점수(정답 유사도)만"

→ 당신이 말한 건 **프롬프트를 *점수로* 최적화**하는 거예요. 프롬프트엔 *정답이 없고*(어떤 프롬프트가 정답인지 미리 모름), 오직 *결과 점수*만 있죠. 이건 오늘 배운 강화학습 구조예요 — 정답 베끼기(지도)가 아니라, *결과를 채점해 좋은 걸 탐색*. 정확히는 자동 프롬프트 최적화(APO) — RL의 친척이에요.

진짜 지도학습이려면: 파서 *모델 가중치*를 expected.json에 맞게 학습해야 해요. 근데 doc-ingest는 외부 엔진(opendataloader·PyMuPDF)을 써서 가중치 통제가 약하고, 라벨도 많이 필요 → 무겁고 안 맞아요.

**그리고 — doc-ingest는 이미 강화학습 *판*이 깔려 있어요:
- validator(채점) = 보상 함수
- miss_log(실패 적재) = 탐색 신호
- 이미 reward harness가 있는 거예요. 그래서 적용이 자연스러워요.

추천 경로 (가벼운 → 무거운):
1. 자동 프롬프트 최적화**: validator 점수를 보상으로, *LLM이 프롬프트 변이를 제안*(Reflexion/OPRO식) → 점수 오르면 채택. 가중치 학습 0, 가장 싸고 빠름. ← 여기서 시작.
2. 전략 선택 정책: registry가 opendataloader냐 text_layer냐 고르는 걸, 문서 프로파일 feature 기반 *밴딧*으로 학습.
3. (무겁게) 소형 모델 파인튜닝 / 리워드모델 RL — 라벨 충분할 때만.

**⚠️ 결정적 경고 — 오늘 배운 게 *여기서* 칼이 돼요:

> 한 문서의 정답지에 프롬프트를 맞추면 = 과적합. 그 문서만 100점, 나머지는 더 나빠져요. (名可名 非常名 / 100%는 부러진다 / 일반화)

- 반드시 다양한 문서 묶음(batch)**의 *평균 점수*를 올리고, held-out 검증셋으로 일반화 확인.
- 굿하트 주의: 단일 유사도 점수 하나만 목표 삼으면 그 지표만 *해킹*돼요. → 여러 지표(구조 정확도·텍스트 정확도·표 정확도)를 섞고 갱신.

한 줄: 당신 직관에서 *신호의 출처*(정답지)는 맞아요. 하지만 *메커니즘*은 지도가 아니라 RL/탐색이고, 무엇보다 **한 문서가 아니라 *문서 분포*에 맞춰야 해요. 그게 doc-ingest의 miss_log 루프와 정확히 맞물려요.

## 1) 무엇이 바뀌나
- 라벨 생김 → "새 파싱이 정답에 얼마나 가깝나"를 *점수로* 잴 수 있음. 채점은 지도학습처럼 명확해졌어요.
- 단, 프롬프트를 *고치는 방식*은 여전히 점수 기반 탐색(RL 계열)이에요 — "정답 프롬프트"는 없으니까. **정답은 *출력*에 있지 *프롬프트*에 있지 않아요.

## 2) 갈림길 — 당신이 원래 "지도학습"이라 한 그것
- Path A (가벼움·추천)**: 외부엔진+LLM 프롬프트 유지 → *프롬프트를 점수로 최적화*. 가중치 학습 0.
- **Path B (무거움·*진짜* 지도학습)**: (PDF/텍스트 → 좋은 파스) 쌍으로 *추출 모델을 파인튜닝*. 모델이 내재화. 라벨 많이 필요.

→ 당신 직관(지도학습)은 Path B인데, 목적엔 Path A가 더 싸고 맞아요.

## 3) ⚠️ 숨은 칼 — "내 파싱을 정답으로"의 *천장*

이게 제일 중요해요. 당신 정답지는 *하늘에서 온 진리*가 아니라 *지금 당신의 최선*이에요. 거기에 맞춰 최적화하면 —

- 그 정답을 *흉내내는* 거라 **당신의 현재 수준을 *넘지 못해요.* (천장 = 레퍼런스 품질)
- 오늘 알파고와 정반대예요**: 알파고는 "사람 수를 흉내내라"가 아니라 *"이겨라"(독립된 결과)*로 보상받아 사람을 *넘었어요.* "내 파스를 맞춰라"는 흉내(지도)라 나를 못 넘어요.
- 레퍼런스에 *오류*가 있으면 그 오류까지 배워요. (名可名 — 고정한 정답을 진리로 믿으면 그 한계에 갇힘)

그러니 정직하게, 목적부터 정해야 해요:

- **"싼 경로(LLM 프롬프트)를 *내 현재 최선*만큼 끌어올려 새 문서에 *대량 적용*" → 완벽해요. Path A로.
- "파싱을 *지금보다 더* 잘하게" → "내 파스 흉내"로는 안 돼요. 독립된 품질 신호(규칙 검증, 사람이 확인한 어려운 케이스, 또는 다운스트림 성공 — 예: law-matcher가 맞았나)가 보상이어야 천장을 뚫어요.

## 4) 구체 레시피 (Path A)
- 정답지 분리: train / validation / test
- 거리(보상) 정의가 진짜 일이에요** — "가장 가깝게"를 구체화: *블록 텍스트 F1 + 구조 점수 + 표 셀 정확도*의 가중합. 이게 없으면 시작 못 해요.
- 루프: 프롬프트 → train 평균 점수 → (LLM이 프롬프트 수정 제안) → validation 오르면 채택
- test(한 번도 안 본 것)로 일반화 확인 — 한 문서 외우기 방지
- 떨어진 케이스 → miss_log → 정답지에 추가 (doc-ingest 축적 루프 그대로)

## 데이터 쪽 — "한 문서 외우기" 막기
- train / validation / test 분리 — test는 *끝까지 안 본다*. 마지막에 딱 한 번.
- 문서 다양성 확보 — 같은 *종류*(예: 같은 기관 양식)만 잔뜩이면, 그 양식에 과적합해요. 스캔본/텍스트본, 표 많은 것/적은 것, 단/다단, 깨끗한 것/지저분한 것을 *섞어서*.
- 배치로 평균 — 프롬프트를 *한 문서* 점수가 아니라 *여러 문서 평균* 점수로 평가. (오늘 배운 미니배치 — 한 표에 안 휘둘리기)

## 목표(보상) 쪽 — 굿하트 막기
- 단일 점수 금지 — "유사도 하나"만 올리면 그 지표만 해킹돼요. *구조 + 텍스트 + 표* 여러 축을 가중합, 그리고 가끔 갱신.
- **지표를 *움직이는 과녁*으로 — 고정 검증셋만 보면 거기 과적합. 주기적으로 새 문서를 검증셋에 투입.

## 프롬프트 쪽 — "여백" 남기기
- 과하게 길고 구체적인 프롬프트 경계** — 특정 문서 사례를 프롬프트에 *박아넣으면*(예: "○○기관 양식은 이렇게") 그게 과적합이에요. 일반 규칙으로 추상화.
- 100%를 노리지 않기 — train 점수 100% 찍으면 오히려 의심. (堅强則折 — 굳으면 부러진다) validation이 같이 안 오르면 멈춤.

## 운영 쪽 — 축적 루프
- miss_log → 정답지 성장 — 실패 케이스를 계속 픽스처로 박제. 정답지가 *커지고 다양해질수록* 과적합 여지가 줄어요. (doc-ingest 원래 철학 그대로)
- early stopping — validation 점수가 *떨어지기 시작하면* 거기서 멈춤. 그 지점이 일반화 정점.

---

한 가지만 덧붙이면 — **과적합 방지의 본질은 "train을 잘하는 것"이 아니라 "train과 validation의 *간극*을 보는 것"**이에요.

``
train 점수 ↑  &  validation 점수 ↑   → 진짜 좋아지는 중 ✅
train 점수 ↑  &  validation 점수 ↓   → 외우기 시작 (과적합) ⚠️ 멈춰
`

그 *두 곡선의 벌어짐*만 계속 지켜보면 돼요. 그게 "하나의 완벽을 포기하고 전체에 강해진다"를 *숫자로 보는* 방법이에요.
